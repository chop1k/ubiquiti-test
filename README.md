# Тестовое задание

Решение тестового задания на PHP «Обработка заказов». CLI-скрипт читает список заказов в формате JSON из стандартного ввода и выводит статистику по оплаченным заказам: их количество, общую сумму и самый дорогой заказ. Некорректные данные обрабатываются, как описано в разделе «Обработка ошибок». Из дополнительных заданий реализованы группировка заказов по статусам (вариант Б) и сохранение результата в JSON-файл (вариант В).

## Структура проекта

```
orders.php           точка входа: подключает автозагрузку Composer (с проверкой версии PHP) и вызывает main()
src/orders.php       вся логика: разбор JSON, валидация заказов, подсчёт статистики, вывод и сохранение результата
examples/            тестовые данные: исходный пример из задания и файлы с некорректными данными
composer.json        требование PHP >= 8.1 и подключение src/orders.php через автозагрузку
LICENSE              текст лицензии MIT
```

Точка входа вынесена в отдельный файл без синтаксиса PHP 8: на старой версии PHP должна сработать проверка Composer с понятным сообщением, а не ошибка разбора.

## Запуск

Требуется PHP 8.1+ и Composer.

```bash
composer install
php orders.php < examples/orders.json
cat examples/orders.json | php orders.php --output=result.json
```

Опции:

| Опция | Назначение |
|---|---|
| `--strict` | остановиться на первом некорректном заказе или при переполнении итоговой суммы |
| `--no-round` | не округлять дробные суммы при выводе |
| `--output=FILE` | сохранить результат в JSON-файл (вариант В) |
| `-h`, `--help` | справка |

Группировка по статусам (вариант Б) выводится всегда.

Коды выхода: `0` — успех, `1` — фатальная ошибка, `2` — результат посчитан, но часть заказов пропущена.

Ещё два случая возникают до запуска самой обработки:
- нет каталога `vendor/` (не выполнен `composer install`): сообщение `Не найден vendor/autoload.php. Выполните composer install.`, код 1;
- версия PHP ниже 8.1: скрипт останавливает проверка платформы Composer с сообщением `Composer detected issues in your platform: Your Composer dependencies require a PHP version ">= 8.1.0". You are running 8.0.30.` и stack trace. Код выхода 255: так PHP завершается при необработанном исключении. Проверено в официальном образе `php:8.0-cli`.

В каталоге `examples/` лежат файлы с некорректными данными для проверки обработки ошибок.

## Обработка ошибок

Результат пишется в STDOUT, ошибки и предупреждения пишутся в STDERR.

**Фатальные ошибки (код 1, без результата):**
- ввод пустой, JSON не декодируется или корень не массив (например, `{}` или `null`);
- данные не переданы через stdin (скрипт запущен без перенаправления ввода);
- неизвестный аргумент или не удалось записать файл `--output`;
- итоговая сумма оплаченных заказов превышает максимальное значение float (≈ 1,8·10³⁰⁸) и становится бесконечностью. Это проверяется и без `--strict`;
- с `--strict`: итоговая сумма оплаченных заказов превышает `PHP_INT_MAX`.

**Некорректный заказ:** заказ пропускается, в STDERR пишется предупреждение с индексом и id заказа, обработка остальных продолжается, код выхода 2. С флагом `--strict` первый же некорректный заказ становится фатальной ошибкой. Некорректным считается заказ, если:
- элемент массива не является объектом;
- отсутствует одно из полей `id`, `customer`, `amount`, `status`;
- `id` не положительное целое число;
- `customer` не непустая строка;
- `amount` не число (строка `"1500"` тоже не принимается: неявное приведение скрыло бы ошибку источника данных) или число отрицательное (включая `-1e309`, которое `json_decode` превращает в минус бесконечность), или число слишком большое для float (`1e309` и больше: `json_decode` превращает такое число в бесконечность). Ноль допустим, потому что по условию заказ 104 с суммой 0 считается оплаченным;
- `status` не входит в список `paid`, `pending`, `cancelled`, `refunded`. Сравнение регистрозависимое, поэтому `"Paid"` считается неизвестным статусом;
- `id` повторяется. Повтор отбрасывается, чтобы одна оплата не учлась дважды.

**Другие решения:**
- если оплаченных заказов нет, это не ошибка: количество и сумма равны 0, самый дорогой заказ выводится как «нет»;
- при равных суммах самым дорогим считается заказ, встретившийся первым;
- дробные суммы допустимы. Расчёт ведётся без округления, а выводимые суммы по умолчанию округляются до 2 знаков (копеек), в терминале и в файле `--output`. Поэтому `0.1 + 0.2` выводится как `0.30`, а `10.005` как `10.01`. Опция `--no-round` отключает округление и выводит значения как есть, например `0.30000000000000004`. В сообщениях об ошибках суммы всегда выводятся как есть, без округления и независимо от `--no-round`: иначе `-0.004` показалось бы как `0.00` и скрыло бы ошибку;
- предполагается, что суммы сравнительно небольшие: целые суммы и их итог не превышают `PHP_INT_MAX` (на 64-битном PHP ≈ 9,2·10¹⁸, на 32-битном ≈ 2,1·10⁹), а любые суммы, записанные как float (`1500.5`, `1500.0`, `1e20`), и итог с их участием не превышают 2⁵³ (≈ 9·10¹⁵):
  - отдельная целая сумма больше `PHP_INT_MAX` отклоняется как некорректный тип;
  - если итог целых сумм превышает `PHP_INT_MAX`, PHP молча переходит на float и точность теряется. Без `--strict` скрипт это не отслеживает, с `--strict` это фатальная ошибка (код 1). Проверка `--strict` работает, только пока итог остаётся целым, поэтому результат зависит от порядка заказов: если перед большими целыми суммами в списке встретилась дробная (`0.5`), итог уже стал float, и переполнение **не ловится**, а если дробная сумма идёт после, переполнение ловится;
  - float больше 2⁵³ теряет точность молча, уже при декодировании JSON или при сложении. Этого **не ловит даже `--strict`**, и `--no-round` здесь тоже не помогает;
  - float, превысивший максимум (≈ 1,8·10³⁰⁸), становится бесконечностью. Это отслеживается всегда: такая сумма в заказе делает заказ некорректным, а такой итог даёт фатальную ошибку;
- BOM в начале ввода игнорируется;
- файл `--output` записывается атомарно: сначала во временный файл, затем переименование;
- путь для `--output` указывается только через `=` (`--output=FILE`). Форма через пробел намеренно не поддерживается, чтобы следующий аргумент не принялся за путь: иначе `--output --strict` создал бы файл `--strict`, а строгий режим не включился бы.

**Известные ограничения:**
- управляющие символы во входных данных не экранируются. Сырые управляющие байты и битый UTF-8 отклоняет `json_decode`, но экранированные последовательности вроде `\u001b` допустимы в JSON. Если такая последовательность есть в поле `status` или в строковом `id`, она попадёт в текст предупреждения в STDERR как есть и может исказить отображение в терминале: например, перевести строку или стереть уже выведенное. Мы знаем об этой проблеме и осознанно не обрабатываем её. На расчёт, результаты и код выхода она не влияет, а в худшем случае искажается только отображение предупреждений.

## Примеры обработки ошибок

Вывод ниже получен реальным запуском команд, stdout и stderr показаны вместе.

### Отрицательные суммы

Отрицательная сумма делает заказ некорректным при любом статусе, а `-0.0` считается нулём. Сумма в сообщении выводится без округления, поэтому `-0.004` не превращается в `0.00`. Без флага такие заказы пропускаются, а с `--strict` скрипт откажется работать с невалидными данными и остановится на первом же некорректном заказе.

```
$ php orders.php < examples/negative_amount.json; echo "exit: $?"
Предупреждение: заказ [1] (id 102): поле "amount" не может быть отрицательным (-100)
Предупреждение: заказ [2] (id 103): поле "amount" не может быть отрицательным (-0.5)
Предупреждение: заказ [4] (id 105): поле "amount" не может быть отрицательным (-2500)
Предупреждение: заказ [5] (id 106): поле "amount" не может быть отрицательным (-0.004)
Количество оплаченных заказов: 2
Общая сумма оплаченных заказов: 1500.00
Самый дорогой оплаченный заказ: № 101 на сумму 1500

Заказы по статусам:
  paid: 2
  pending: 0
  cancelled: 0
  refunded: 0
Пропущено некорректных заказов: 4
exit: 2

$ php orders.php --strict < examples/negative_amount.json; echo "exit: $?"
Ошибка: заказ [1] (id 102): поле "amount" не может быть отрицательным (-100)
exit: 1
```

### Переполнение итоговой суммы

Без `--strict` PHP молча переходит на float и точность теряется (см. допущения выше). С `--strict` это фатальная ошибка.

```
$ php orders.php < examples/overflow.json; echo "exit: $?"
Количество оплаченных заказов: 2
Общая сумма оплаченных заказов: 9223372036854775808.00
Самый дорогой оплаченный заказ: № 1 на сумму 9223372036854775807

Заказы по статусам:
  paid: 2
  pending: 0
  cancelled: 0
  refunded: 0
exit: 0

$ php orders.php --strict < examples/overflow.json; echo "exit: $?"
Ошибка: Итоговая сумма оплаченных заказов превышает PHP_INT_MAX, результат был бы неточным
exit: 1
```

### Бесконечность

Слишком большая сумма в заказе делает заказ некорректным. Если бесконечностью становится итог, это фатальная ошибка и без `--strict`.

```
$ php orders.php < examples/infinity.json; echo "exit: $?"
Предупреждение: заказ [1] (id 102): поле "amount" превышает максимально допустимое значение
Количество оплаченных заказов: 1
Общая сумма оплаченных заказов: 1500
Самый дорогой оплаченный заказ: № 101 на сумму 1500

Заказы по статусам:
  paid: 1
  pending: 0
  cancelled: 0
  refunded: 0
Пропущено некорректных заказов: 1
exit: 2

$ php orders.php < examples/infinity_sum.json; echo "exit: $?"
Ошибка: Итоговая сумма оплаченных заказов превышает максимальное значение float
exit: 1
```

### Неизвестный статус

Статус сравнивается с учётом регистра, поэтому `Paid` тоже считается неизвестным.

```
$ php orders.php < examples/unknown_status.json; echo "exit: $?"
Предупреждение: заказ [1] (id 102): неизвестный статус "shipped"
Предупреждение: заказ [2] (id 103): неизвестный статус "Paid"
Количество оплаченных заказов: 1
Общая сумма оплаченных заказов: 1500
Самый дорогой оплаченный заказ: № 101 на сумму 1500

Заказы по статусам:
  paid: 1
  pending: 0
  cancelled: 0
  refunded: 0
Пропущено некорректных заказов: 2
exit: 2
```

### Ошибки в JSON

Битый JSON, пустой ввод и корень не-массив останавливают обработку с кодом 1.

```
$ php orders.php < examples/invalid_json.json; echo "exit: $?"
Ошибка: Не удалось декодировать JSON: Syntax error
exit: 1

$ php orders.php < examples/empty.json; echo "exit: $?"
Ошибка: Пустой ввод: ожидался JSON-массив заказов
exit: 1

$ php orders.php < examples/not_a_list.json; echo "exit: $?"
Ошибка: Ожидался JSON-массив заказов, получено: объект
exit: 1
```
